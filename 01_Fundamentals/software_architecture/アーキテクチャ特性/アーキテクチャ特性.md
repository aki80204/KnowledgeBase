次の基準を満たすもの
- ドメインによらない、設計に関する考慮事項を明らかにするもの
- 設計の構造的な側面に影響を与えるもの
- アプリケーションの成功に不可欠かつ重要なもの

## 5. 示唆・実務への適用
アーキテクトとドメインのステークホルダーが会話すると会話がかみ合わないことが起こる。ドメインの関心毎を[[アーキテクチャ特性]]に翻訳することが重要となる。

| ドメインの関心毎| [[アーキテクチャ特性]] |
| :--- | :--- |
| 合併・買収 | [[相互運用性]]、[[スケーラビリティ(Scalability)]] 、[[適応性]]、[[拡張性(Extensibility)]] |
| 市場投入までの時間 | [[アジリティ]]、[[テスト容易性]]、[[デプロイ容易性]] |
| ユーザー満足度 | [[パフォーマンス(Peformance)]]、[[可用性(Availability)]]、[[耐障害性]]、[[テスト容易性]]、[[デプロイ容易性]]、[[アジリティ]]、[[セキュリティ(Security)]] |
| 競争優位性 | [[アジリティ]]、[[テスト容易性]]、[[デプロイ容易性]]、[[スケーラビリティ(Scalability)]]、[[可用性(Availability)]]、[[耐障害性]] |
| 時間と予算 | シンプルさ、[[フィージビリティ]] |
